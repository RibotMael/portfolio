Fonctionnalités

Ce que fait l'application

Participants simples

Ajout un par un ou import d'une liste (virgules ou retours à la ligne). Les doublons sont détectés.

Interdictions ciblées

Chaque règle « A ne peut pas offrir à B » peut avoir un motif (couple, déjà offert l’an dernier…) et être rendue mutuelle.

Tirage par backtracking

Le solveur teste les attributions avec retour arrière, en traitant d'abord les donneurs les plus contraints (MRV).

Diagnostic d'impasse

Si aucun tirage n'est possible, l'application indique quel participant est bloqué ou que les règles se contredisent.

Liens de révélation privés

Chaque participant reçoit un lien qui n'affiche que son propre destinataire, sans que l'organisateur le voie.

Sauvegarde locale

Participants, règles et tirage sont conservés dans le navigateur : aucun serveur, aucune inscription.

Algorithme

Un tirage sous contraintes

Un simple mélange ne suffit pas dès qu'il y a des interdictions : il peut mener à une impasse. Le problème est traité comme une affectation avec contraintes, résolue par retour arrière.

// Les donneurs les plus contraints sont traités en premier (MRV)
const orderedGivers = [...participants].sort(
  (a, b) => allowedReceivers.get(a).length - allowedReceivers.get(b).length
);

function backtrack(index) {
  if (index === n) return true;
  const giver = orderedGivers[index];
  for (const candidate of allowedReceivers.get(giver)) {
    if (!usedReceivers.has(candidate)) {
      usedReceivers.add(candidate);
      currentAssignment[giver] = candidate;
      if (backtrack(index + 1)) return true;
      usedReceivers.delete(candidate);  // retour arrière
      delete currentAssignment[giver];
    }
  }
  return false;
}

Limites

Points d'amélioration

⚠️ Les liens de révélation encodent le couple donneur / destinataire en Base64 dans l’URL : ils protègent du regard, pas d’une personne qui sait décoder. Une version serveur ou un chiffrement (par exemple Web Crypto) permettrait de renforcer la confidentialité.
